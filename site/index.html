Qual arquivo baixar?

Para jogar, baixe só o EXE.

Cliente recomendado — EXE standalone: serve para jogar, entrar em salas e também criar uma sala no próprio PC. Você não precisa baixar o servidor dedicado.

Cliente ZIP: é apenas uma alternativa ao EXE standalone; não é necessário baixar os dois.

Servidor dedicado ZIP: use somente se quiser rodar o servidor separado do cliente, em outra máquina ou processo. Nesse caso, extraia o ZIP e mantenha todos os arquivos juntos.

Carregando releases…

O EXE standalone já inclui o necessário para o uso normal do NavBR. O PC de quem cria a sala funciona como host pela porta TCP 27730. O pacote do servidor é opcional e destinado apenas ao modo dedicado.

Experiência NavBR

Feito para dirigir, não para atrapalhar.

⌖

GPS integrado

Roadmap do próprio mapa, posição, heading, zoom de até 10×, rota ativa, destino e próxima parada.

▣

HUD sobre o OMSI

Minimapa móvel e translúcido, chat visual, atalhos em jogo, contador de jogadores e indicador de voz.

⇄

Peer-host

Quem cria a sala hospeda a sessão no próprio PC. O servidor dedicado continua opcional.

◉

Voz Opus

NAudio + Concentus, 48 kHz mono, frames de 20 ms e push-to-talk configurável.

⌨

Atalhos protegidos

F9/F10 e combinações com Shift/Ctrl são comparadas com o keyboard.cfg real do OMSI.

◎

Sem Steam API

O NavBR detecta Omsi.exe em execução e encontra a instalação diretamente pelo processo.

Preparação do mapa

Roadmap visual e rota são coisas diferentes.

O NavBR lê a instalação real do mapa. Para o fundo visual do GPS, o arquivo recomendado é texture\map\whole.roadmap.bmp. O traçado da linha continua vindo do TTData e da geometria do mapa.

Em desenvolvimento para a alpha.10: o cliente passa a listar todos os mapas instalados em dois grupos — roadmap pronto e roadmap ausente. Mapas com apenas roadmaps individuais de tiles não são marcados incorretamente como prontos.

Abrir guia completo
01

Abra o OMSI Editor

Inicie o Editor, carregue o mapa e abra a aba Tile.

02

Use Create Roadmap

O Editor gera os roadmaps das tiles e, quando possível, o whole.roadmap.bmp.

03

Confira a pasta correta

O caminho recomendado é maps\<mapa>\texture\map\whole.roadmap.bmp.

04

Veja a lista no NavBR

Na alpha.10, mapas prontos aparecem primeiro com nome, pasta, quantidade de tiles e o arquivo de roadmap global detectado.

Sala multiplayer

O criador da sala já é o servidor.

O NavBR inicia um host ASP.NET Core + SignalR dentro do PC do criador. Não é necessário baixar o servidor dedicado para uma sala comum.

01

Crie ou entre em uma sala

Presença, telemetria, jogadores no mapa, chat e voz já fazem parte da implementação atual.

02

Porta TCP 27730

Em LAN o endereço local pode ser usado diretamente. Pela Internet ainda pode ser necessário firewall e port forwarding.

03

Reconexão automática

O cliente SignalR tenta reconectar e reentrar na sala após uma queda temporária.

Transparência de testes

Alpha significa alpha.

O CI valida compilação, cliente x86, EXE standalone e recursos do pacote. A base do multiplayer já existe no código. HUD, traçado corrigido da linha, próxima parada, multiplayer entre PCs, voz e atalhos ainda precisam de validação completa no OMSI real.

Pesquisa em paralelo

Ônibus remotos dentro do próprio OMSI.

A alpha.10 prepara uma integração opcional via plugin x86. O multiplayer atual continua independente do plugin e segue funcionando apenas com o cliente NavBR.

Documento técnico →
DLL

Plugin opcional x86

Protótipo DLL + OPL com callbacks do OMSI e diagnóstico por heartbeat. Ainda não cria nem move veículos no simulador.

↔

Bridge local implementado

Windows Named Pipes já ligam cliente e plugin no mesmo PC, com protocolo versionado, handshake e reconexão sem abrir outra porta pública.

✓

Filtro e segurança

O plugin recebe o contexto local, filtra remotos pelo mapa/fingerprint, limita 64 estados e remove automaticamente dados com mais de 5 segundos.

≈

Movimento suavizado

Dois snapshots por jogador já alimentam interpolação de X/Y/Z, velocidade e heading com atraso aproximado de 100 ms antes do futuro spawn.

Próximo marco: validar DLL, heartbeat e fluxo SignalR → cliente → Named Pipe → plugin no OMSI 2.3.004. Só depois será tentada a primeira entidade remota física.
